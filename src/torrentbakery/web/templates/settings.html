Einstellungen

Hier legst du fest, woher TorrentBakery seine Daten holt und wohin die Torrents gehen. Für den Normalfall (Szene aus Stash backen) brauchst du nur die ersten beiden Punkte.

  • {{ "✅" if c.stash.url else "⬜" }} Stash verbinden nötig für Stash-Szenen
  • {{ "✅" if c.trackers else "⬜" }} Tracker-Profil anlegen nötig für Torrents
  • {{ "✅" if c.web_media_roots else "⬜" }} Medienordner freigeben nur für einzelne Dateien
  • {{ "✅" if hamster_key else "⬜" }} Bildhoster optional
  • {{ "✅" if c.stashboxes else "⬜" }} Stash-box (StashDB) optional

Jede Änderung wird sofort gespeichert und gilt für den nächsten Bake. Gespeicherte API-Keys werden nie wieder angezeigt.

1. Stash nötig für Stash-Szenen

Die Verbindung zu deiner Stash-Instanz. Darüber findet TorrentBakery deine Szenen (Suche auf der Startseite) und liest Titel, Studio, Darsteller, Tags und den Dateipfad aus. Ist die Szene in Stash mit StashDB verknüpft, kommen die Metadaten und das Titelbild von dort.

So, wie du Stash im Browser aufrufst: mit http:// und Port, ohne /graphql am Ende.

In Stash unter Einstellungen → Sicherheit → API-Key. Hat Stash kein Passwort, bleibt das Feld leer.

„Verbindung testen“ prüft die eingetragenen Werte, auch ohne vorher zu speichern.

Pfad-Zuordnung (Stash-Pfad → Pfad in diesem Container), nur bei abweichenden Pfaden

Stash meldet den Speicherort jeder Datei. Sieht dieser Container dieselbe Freigabe unter einem anderen Pfad, übersetzt diese Tabelle den Anfang des Pfads. Erkennbar daran, dass das Backen mit „… existiert hier nicht“ abbricht. Liegen die Dateien bei beiden unter demselben Pfad (z. B. /media/BF-stshpp), lass die Tabelle leer.

2. Tracker-Profile nötig für Torrents

Ein Profil bündelt, was dein Tracker (oder Forum) für den Torrent verlangt. Beim Backen wählst du ein Profil aus; ohne Profil entsteht ein Torrent ohne Announce-URL, den kein Tracker annimmt. Du kannst beliebig viele Profile anlegen, z. B. eines pro Tracker.

{% for name, t in c.trackers.items() %} {% else %}{% endfor %}
{{ name }}
{{ t.announce | map("urlhost") | join(", ") }} · Source „{{ t.source or "–" }}“ · {{ "privat" if t.private else "öffentlich" }}
Noch kein Profil angelegt.

Profil hinzufügen oder ersetzen

Frei wählbar, erscheint auf der Startseite im Auswahlfeld. Gleicher Name = Profil wird ersetzt.

Manche private Tracker verlangen im Torrent ein „source“-Feld (steht in deren Upload-Regeln). Sonst leer lassen.

Die persönliche Announce-URL von der Upload-Seite deines Trackers, meist mit deinem Passkey. Mehrere URLs: eine pro Zeile. Die Seite zeigt später nur den Servernamen, nie den Passkey.

Schaltet DHT und Peer-Austausch aus. Für private Tracker an lassen, nur für öffentliche Tracker abschalten.

3. Medienordner nur für einzelne Dateien

Auf der Startseite kannst du statt einer Stash-Szene auch einen Dateipfad wie /media/BF-stshpp/Film/film.mkv eingeben. Aus Sicherheitsgründen erlaubt die Oberfläche das nur in den Ordnern, die hier stehen. Szenen aus Stash brauchen diese Einstellung nicht.

Ein Ordner pro Zeile, Unterordner sind eingeschlossen. Der Ordner muss in diesem Container eingehängt und lesbar sein.

4. Bildhoster optional

Ohne Hoster entstehen Titelbild und Screenshot-Übersicht nur als Dateien zum Herunterladen; im Forenpost stehen dann Dateinamen, und du lädst die Bilder selbst hoch. Mit Hoster lädt TorrentBakery die Bilder beim Backen hoch und setzt die Links in den Post. Den Hoster wählst du auf der Startseite pro Bake.

pixhost.to, pixhost.cc, pixho.st, imgbox, imagebamFunktionieren ohne Konto und ohne Einstellungen.

Im hamsterimg-Konto unter dem Punkt für die API. Nur nötig, wenn du hamsterimg als Hoster verwenden willst.

5. Stash-box (z. B. StashDB) optional

Nur für den Fall, dass du eine normale Datei backst und ihre Metadaten trotzdem von StashDB willst (Feld „Stash-box-URL“ auf der Startseite). Szenen aus Stash holen die Metadaten über den Key, den Stash selbst schon kennt, dafür brauchst du hier nichts.
